# ADR-008：文档索引事务 Outbox 与重建边界

> 状态：已接受
> 日期：2026-09-14

## 背景

gin-backend 拥有正式文档、不可变版本、访问策略和生命周期事实；mixin-search 拥有可重建的控制状态与向量索引。两者没有共享事务，文档写入不能因为远程索引服务不可用而失败，也不能在提交后丢失索引意图。

阶段 1 删除的旧 `index_outbox` 没有与当前 v1 契约、修订 fencing 和 Worker 消费闭环连接，不能直接恢复。P2.3 需要建立与当前模型一致的可靠传播边界，并继续让 PostgreSQL BM25 承担正式读取。

## 决策

### 1. 事件与文档事实同事务提交

每次文档聚合变更写入一个 `document_index_delivery_events` 事件。事件保存文档/版本标识、内容哈希、聚合/访问/生命周期修订以及规范化的小型空间授权快照；正文仍只存在于不可变文档版本中，Outbox 不复制正文。

文档事实、BM25 投影和投递事件在同一个 PostgreSQL 事务中提交。事务回滚会同时撤销事实和事件，事务内不进行网络调用。

### 2. 独立 Worker 顺序消费

`document-index-worker` 独立于 HTTP 进程运行。领取查询只允许并发 Worker 获得每个文档最早的未完成事件，并使用数据库租约与 lease token fencing 防止过期执行者提交结果。

同步事件按以下顺序执行：

1. 索引不可变版本；
2. 更新访问策略；
3. 激活版本。

正常更新不删除旧版本；活动版本和生命周期 fencing 决定可检索状态。版本删除和文档删除使用各自的显式事件。

### 3. 幂等、重试与死信

事件 ID 是稳定根标识，各远程子操作使用 `{event_id}/index`、`{event_id}/access`、`{event_id}/activate` 或对应删除后缀。模糊超时和进程重启必须复用完全相同的操作 ID。

可重试故障进入带上限的确定性全抖动退避；永久错误或达到尝试上限进入死信。同一文档的死信会阻塞后续事件，管理员重放后恢复顺序消费。

### 4. 对账与全量重建

对账读取 gin-backend 当前事实并调用 `GetDocumentVersionState`。缺失或不一致状态生成幂等同步事件；匹配版本仍可生成访问同步事件，以重放精确 ACL；非活动事实生成删除事件。

全量重建在 repeatable-read 事务内枚举事实并生成带重建运行标识的幂等事件。事务只建立一致快照与投递意图，不执行远程调用。空控制存储和空 Qdrant 由普通 Worker 消费这些事件重建。

## 结果

- mixin-search 不可用不会阻断正式文档写入，恢复后可以继续投递；
- 重复发送、模糊超时和 Worker 接管由持久化幂等与 fencing 收敛；
- 投递表不承担正文存储或正式查询职责；
- P2.3 提供可靠传播与可重建能力；P2.4 已按 [ADR-009](./009-shadow-index-compose-and-health-boundary.md) 完成统一装配、探针与持续影子运行；
- PostgreSQL BM25 继续是正式搜索读取方。

## 验证

- `verify-index-delivery.ps1`：真实 PostgreSQL 事务、顺序、租约、重试、死信和重放；
- `verify-index-rebuild-e2e.ps1`：从空控制 PostgreSQL 与空 Qdrant 重建并验证活动版本、删除状态和搜索结果；
- `apps/gin-backend` 的单元与集成测试覆盖事务回滚、稳定操作 ID 和 gRPC 错误分类。
