# ADR-005：开发基线重建优先于生产迁移

- 状态：已接受
- 日期：2026-09-12

## 背景

当前仓库处于初创项目演变期，没有需要保留的生产业务数据、外部稳定客户端或不停机升级约束。此前阶段为了验证长期可迁移性，引入了迁移账本、校验和、并发锁、备份恢复、反向导出、回滚演练和旧接口兼容；这些机制已经证明设计可行，但继续维护会拖慢当前领域模型和接口收口。

## 决策

1. 当前阶段采用可丢弃开发数据的基线重建方式，允许通过删除本地数据卷重新初始化。
2. 数据库只保留确定性的空库初始化入口、约束和集成验证；不维护已有数据库升级、备份恢复、反向导出和回滚演练。
3. 数据表、Go 包和 HTTP/RPC 接口允许直接破坏性调整；仓库内调用方和测试在同一实施包同步更新，不提供旧接口别名、重定向或双轨兼容。
4. 删除已经退出运行时的旧 Markdown 表、索引和相关初始化资产；未接入的跨服务投递状态与可靠性设施推迟到真实接入前设计。
5. 保留事务一致性、文档版本、权限隔离、BM25 行为、空库启动、编译测试和本地 Compose 健康验收，因为这些属于产品正确性而非生产运维负担。

## 重新引入生产能力的触发条件

出现任一条件时，必须重新设计版本迁移、备份和兼容策略：

- 存在不可丢弃的共享或生产数据；
- 仓库外客户端依赖已发布接口；
- 需要滚动升级、灰度、停机窗口或明确恢复点目标；
- mixin-search 接入真实写入/查询流量，需要可靠投递和重放；
- 项目开始发布可升级版本而不是只维护一个开发基线。

## 结果

- P1.4 改为开发基线重建，并直接清理生产式迁移和旧兼容资产。
- P1.5 完成 mixin-search/v1 契约定型和本地总体验收后，阶段 1 结束。
- 原 P1.6 的备份、恢复、正式切换和回滚闭环取消，不作为当前阶段门禁。
- ADR-004 的长期检索所有权方向继续有效，但其中面向生产流量的影子切换、回退和兼容要求推迟到上述触发条件出现之后。
