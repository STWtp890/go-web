# ADR-014：多语料控制面与索引隔离

> 状态：已接受
> 日期：2026-09-17
> 决策范围：P3.3 及其后的聊天语料接入
> 相关决策：[ADR-007](./007-qdrant-control-projection-and-filtering.md)、[ADR-012](./012-multi-consumer-search-boundary-and-critical-path-shift.md) 决策 6、[ADR-013](./013-immutable-control-snapshot-and-background-projection.md)

## 背景

P3.2 之后，`mixin-search` 的控制面是一份**文档领域**的不可变快照：`controlSnapshot` 的字段全部是文档版本、清单、访问快照、操作账本与待清理向量意图；`storageDomain` 只在渲染向量控制投影时传入，它是**存储隔离**，不是语料类型契约。generation、持久化（单行快照 + compare-and-swap）、发布与后台投影 reconciler 也都属于这一套文档控制状态。

P3.3 要为聊天语料建立契约与索引。最省事的做法是把聊天数据加入同一份快照，但这会固化一批跨语料耦合：

1. **写入成本外溢**：文档快照的每次写入都对全部状态做一次私有副本复制，聊天写入会让文档控制面承担与聊天规模成正比的复制成本；
2. **规模互相牵连**：聊天语料增长直接抬高文档搜索的控制面内存与加载成本；
3. **generation 共享**：任一语料的写入都会让另一语料的读者重新加载整份快照；
4. **故障域合并**：任一语料的重建、投影失败或扩容都会影响另一语料；
5. **门禁失真**：P3.5 的在线可靠性门禁会在已经固化的跨语料耦合上测量，得到的 SLO 与压测结论无法归因。

这还是一个**架构决策**而不是实现细节：一旦聊天 RPC 落在文档契约上（例如给 `SearchDocuments` 增加 `corpus_type`），后续拆分就要同时改动协议与所有调用方。

## 决策

### 1. 文档与聊天拥有独立的控制面实例

- 保留现有 `DocumentIndexService` 与文档控制快照，作为文档语料的控制面；
- 聊天语料建立**自己的领域契约**与**自己的控制服务**；
- 两侧各自拥有独立的 generation、独立的持久化状态（各自的 namespace 或表）、独立的投影 reconciler、独立的索引集合与 alias。

### 2. 复用机制，不复用状态

不可变快照、generation compare-and-swap、发布后收敛、后台 reconciler、capability 边界、审计与限流都是**实现模式**，允许两侧各自实现，或在被证明稳定后提取为共享内部包。

**禁止共享一份可变控制状态或 generation**：跨语料共享的是代码形状，不是运行状态。

### 3. 联合检索只在查询编排层融合

跨语料查询由编排方（`py-agent` 或未来的统一检索入口）分别调用两个语料边界，在**结果层**合并并保留语料来源。

- 控制面不合并语料；
- `SearchDocuments` 不增加 `corpus_type`，也不接受聊天请求；
- 聊天契约不接受文档语义的字段（版本激活、墓碑、`lifecycle_revision` 等）。

### 4. 索引、生命周期与重建隔离

- 独立集合、独立 alias 切换、独立重建编排与删除传播；
- 一个语料的重建**不得**切换另一个语料的 alias；
- 聊天消息的撤回、归档与可检索状态是聊天领域自己的状态机，不复用文档的墓碑语义。

### 5. 授权隔离

capability 的 audience 与角色按服务/语料划分；文档授权撤销的生效**不依赖**聊天侧任何状态，聊天侧故障也不影响文档检索的授权判定。

## 结果与权衡

- **成本**：两套控制面骨架（服务、持久化、reconciler）在概念上重复；共享机制若不显式提取，会出现两份实现漂移。这是刻意支付的代价，用来换取故障域与规模域的隔离。
- **收益**：任一语料的规模、故障、重建与扩容不再影响另一语料；P3.5 可以分别定义 QQ/Agent 与 Web 文档搜索的 SLO 并分别压测。
- **明确不做**：不做"多语料单快照"，也不做跨语料的联合事务；需要跨语料一致性的场景在编排层做补偿，而不是在控制面合并。

## 验证：P3.3 的最低验收条件

- 聊天 generation 变化**不触发**文档快照重新加载（可用控制存储 `Generation`/`Load` 计数断言）；
- 聊天索引重建**不切换**文档 alias；
- 文档授权撤销的生效**不等待**聊天投影收敛；
- 聊天语料规模增长**不增加**文档控制快照的大小；
- 任一语料故障**不污染**另一语料的生命周期状态；
- 文档契约无法表达聊天消息、会话时间线或消息撤回；聊天契约无法返回文档语义的结果。

## 复审条件

- 出现必须跨语料原子提交的产品需求（例如统一的"知识可见性"要同时覆盖文档与聊天）；
- 聊天语料检索被移出 `mixin-search` 的范围；
- 共享机制被证明可以安全提取，且两套控制面的重复成本实测高于隔离收益。
